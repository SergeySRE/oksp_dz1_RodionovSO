# Скриншоты для отчёта ДЗ1

Все команды выполняются в WSL из `~/oksp-coursework`.
Просмотрщик использует системный Python 3 и стандартную библиотеку, Docker для него
не нужен. Он не обращается к сервису/БД и не запускает новую серию.

Снимки пока отсутствуют. Сохраняйте реальные PNG в `docs/screenshots/`
(в Windows: `\\wsl.localhost\Ubuntu\home\rodionov\oksp-coursework\docs\screenshots`).
В кадре оставляйте команду, заголовок, маркер sergey_rodionov и таблицу.
Для широкого вывода разверните терминал; не обрезайте имя исходного файла и дату.
Нельзя изображать просмотр JSON как повторный замер или новый pytest.

## S01 — стенд и объём данных

```bash
cd ~/oksp-coursework
docker compose ps
docker compose exec -T app python -m app.cli data-counts
```

Кадр: имена sergey_rodionov-app/db, состояния app running / db healthy, порты,
маркер схемы и пять реальных количеств таблиц. На момент проверки текущая БД —
WORKING (1 / 200 / 30 / 200000 / 100000).

Имя: `s01_stand_working.png`.
Вставка: §1.3 «Условия» и/или §1.4 «Наполнение», подпись
«Состояние стенда и текущие объёмы рабочего наполнения».
Дата этого снимка относится к проверке стенда, а не к серии 07.10.2026.

Для удобной таблицы обоих сохранённых объёмов (дополнительный кадр не обязателен):

```bash
python3 scripts/view_measurements.py --section inventory
```

Здесь числа — сохранённые показания БД на момент старых серий, что явно отмечено.
Если преподавателю нужен именно отдельный живой вывод SMALL, можно выполнить
`seed --size small`, затем `data-counts`, затем восстановить `seed --size working`.
**Seed удаляет все ручные записи пяти таблиц.** Для просмотра старых результатов
переключение seed вообще не требуется.

## Браузер: порядок и подготовка

Измерительные серии завершены. Действия браузера ниже выполняются отдельно,
не запускайте одновременно measure, seed или pytest.
Сначала снимите список и сводку на текущем каноническом WORKING, затем создавайте
демонстрационную запись. Это позволяет обойтись без переключения на SMALL.

Откройте `http://localhost:8080/login`, войдите demo / demo (если меняли .env,
используйте свои DEMO_LOGIN/DEMO_PASSWORD). Отдельный кадр входа не обязателен:
авторизация видна по имени оператора в навигации остальных экранов.

## S07 — поиск свободного слота и создание

Откройте:

`http://localhost:8080/booking?service_id=1&date_from=2026-01-01&date_to=2026-12-31&page=1&size=5`

Выберите первый свободный слот, запишите его специалиста, услугу, начало и конец.
Введите ФИО `Клиент для отчёта ДЗ1`, контакт `dz1-report@example.test`.
Кадр до отправки: услуга и длительность, даты, таблица свободных слотов,
выбранная радиокнопка, заполненные поля и кнопка «Записать на приём».
Имя: `s07_booking_form.png`.
Вставка: §1.1, UI-1 «Поиск слота и создание записи».

Нажмите «Записать на приём»: браузер перейдёт в карточку фактически созданного id.
Не вписывайте заранее придуманный идентификатор в отчёт.

Дополнительная проверка отказа (без обязательного снимка): до создания откройте
тот же URL во второй вкладке, выберите тот же слот и заполните форму.
После успешного создания в первой вкладке отправьте устаревшую форму во второй:
должен появиться отказ о занятом слоте/пересечении (API 409).
При желании сохраните `s07b_busy_slot.png`; вставка — рядом с основной операцией.
Отказ не создаёт вторую запись.

## S08 — обязательная карточка и отмена

В карточке созданной записи снимите статус «Действующая», фактический номер,
ФИО/контакт, специалиста, услугу с длительностью, время слота, оператора и кнопку отмены.
Имя: `s08a_created_card.png`.

Нажмите «Отменить запись». После обновления снимите тот же номер,
статус «Отменена», время отмены и сообщение об освобождённом слоте.
Имя: `s08b_cancelled_card.png`.
Вставка: §1.1, две части UI-1 «Созданная и отменённая запись со связанными сущностями».
Можно объединить S06–S08 в компактную иллюстрацию; не перегружайте основной отчёт
полноразмерными кадрами — шаблон рекомендует 1–2 иллюстрации интерфейса.

Для проверки освобождения заново выполните поиск из S07 и найдите слот по записанным
специалисту/услуге/времени. Повторное создание не требуется.
После проверки нажмите выход: должен открыться /login; открытие /appointments без
сессии должно вернуть на вход. Отдельные кадры этих действий необязательны.

## После браузерной демонстрации

Создание с последующей отменой оставляет историческую запись: это штатная бизнес-логика.
Количества текущей БД уже не совпадают с исходным WORKING. Не подменяйте ими таблицу
объёмов и не меняйте сохранённые измерительные JSON.

Если нужно вернуть канонический стенд:

```bash
docker compose exec -T app python -m app.cli seed --size working
docker compose exec -T app python -m app.cli data-counts
```

Это удалит демонстрационную запись и прочие ручные изменения. Изображения и файлы
измерений сохранятся. Переснимать измерения после этой ручной демонстрации не нужно.

## Не требуются для этого комплекта

- Новый запуск measure или compare для получения красивого вывода.
- Повтор всего pytest ради иллюстрации: фактическая предыдущая итоговая строка уже
  указана в черновике. Исходный stdout не сохранён; при требовании отдельного кадра
  pytest он должен быть реальным новым прогоном вне измерений, а не нарисованной строкой.
- EXPLAIN, pg_stat_statements, профилирование, нагрузочная генерация, оптимизация и индексы.
