# ДЗ2. Профиль и порядок прогона

Вариант 3, сервис записи на приём, учётная запись `demo`, префикс
`sergey_rodionov`. Команды запуска описаны в [README проекта](../README.md#дз2-нагрузочное-испытание).
k6 посылает один HTTP-запрос на итерацию внутри закрытой сети Compose.

| Операция | Доля | Обоснование |
|---|---:|---|
| Поиск свободных слотов | 28% | Для одного клиента оператор может проверить несколько вариантов времени. |
| Список записей | 25% | Основной экран для просмотра расписания и поиска записи. |
| Карточка записи | 15% | Оператор открывает её, чтобы проверить детали приёма. |
| Справочник специалистов | 10% | Нужен при подборе исполнителя и смене фильтра. |
| Создание записи | 9% | Часть поисков завершается бронированием. |
| Справочник услуг | 8% | Нужен при выборе услуги. Поиск конкретного времени выполняют чаще. |
| Отмена записи | 4% | Оператор отменяет часть сделанных бронирований по запросу клиента. |
| Сводка | 1% | Периодическая проверка загрузки специалистов. |

Тяжёлая операция — `GET /api/summary` за 2026 год. В ДЗ1 на WORKING её
p95 составил 3 323,66 мс. Для испытаний ДЗ2 начальное состояние восстанавливается
перед каждой ступенью. В открытом тесте первый парольный вход выполняется в
`setup()`, пороги применяются к запросам с меткой `phase:load`. В смешанном
сценарии последовательность вызовов повторяет веса на полном блоке из 100
итераций. Короткие прогоны описываем по фактическим счётчикам операций.

Пробный прогон проверяет контракт. Его числа не входят в итоговые серии.
На основных ступенях сохраняем исходный поток метрик, сводку k6, коды
завершения, журнал приложения и временные ряды ресурсов. Нарушение порога
задержки или доли ошибок отражается в сводке и коде k6. Для оценки предела
сводки отдельно смотрим число успешных ответов, таймауты и пропуски.
Таймауты могут завершать итерации без успешного ответа.

Просмотр сохранённой ступени из корня проекта:

```bash
python3 load/show_step.py load/results/<имя>
```

Сценарий `heavy` можно повторить с профилировщиком на найденной частоте
при одном процессе Uvicorn. Исходный файл `profile.txt` содержит свёрнутые
стеки py-spy. Просмотр показывает доли по конечным кадрам стека для вызовов
сервисного кода, в знаменателе все сохранённые снимки. Профиль и временные
ряды относим к конкретному прогону с его временем и настройками.

Основное окно нагрузки отсчитывается от первой итерации k6. Просмотр отдельно показывает число HTTP 2xx за это окно и число 2xx, полученных при ожидании завершения запросов. Частота всех завершённых итераций сохраняется из k6.
