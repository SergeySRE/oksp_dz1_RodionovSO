## Установка и запуск

Получите исходники репозитория и перейдите в его каталог. Затем:

```bash
cp .env.example .env
```

В `.env` замените `SESSION_SECRET` длинной случайной строкой, например полученной командой:

```bash
openssl rand -hex 32
```

Задайте локальный пароль БД. Далее выполните команды в этом порядке:

```bash
docker compose build
docker compose up -d --wait db
docker compose run --rm app python -m app.cli init-db
docker compose run --rm app python -m app.cli seed --size small
docker compose run --rm app python -m app.cli data-counts
docker compose run --rm app pytest -q
docker compose up -d app
```

Интерфейс: http://localhost:8080.
Демонстрационный вход по умолчанию: **demo / demo**.
На SMALL и WORKING интерфейс предлагает период 01.01.2026–31.12.2026, в котором находятся данные seed.
Это фиксированный учебный набор, а не расписание относительно текущей даты.

Проверка работающего сервиса:

```bash
docker compose exec app python -m scripts.check_app --size small
```

Переключение на рабочий объём:

```bash
docker compose run --rm app python -m app.cli seed --size working
docker compose run --rm app python -m app.cli data-counts
docker compose exec app python -m scripts.check_app --size working
```

**Seed заменяет все данные пяти таблиц персональной схемы**, включая записи, созданные вручную.
Его следует запускать, когда пользовательские операции не выполняются.
Команда проверки создаёт временные записи и удаляет только собственные строки; количества исходного набора сохраняются,
но последовательность идентификаторов продвигается. Перед будущими измерениями заново выполните seed.

Состояние, журналы, остановка и повторный запуск:

```bash
docker compose ps
docker compose logs app db
docker compose down
docker compose up -d
```

`down` сохраняет данные в именованном томе.
При изменении кода выполните `docker compose up -d --build app`.

## База данных и правила

Единственный источник структуры таблиц — `app/models.py`.
Команда `init-db` создаёт персональную схему и таблицы через SQLAlchemy metadata;
повторный запуск безопасен, но не мигрирует изменённые модели.

| Таблица | Основные поля и связи |
|---|---|
| users | id PK, login, password_hash, full_name |
| specialists | id PK, full_name, specialization |
| services | id PK, name, duration_minutes |
| slots | id PK, specialist_id FK, service_id FK, starts_at, ends_at |
| appointments | id PK, slot_id FK, created_by_id FK, client_name, client_contact, status, created_at, cancelled_at |

Роль одна: оператор. Все записи доступны оператору; регистрации и отдельных клиентов нет.
Сессия — подписанная cookie с HttpOnly, SameSite=Lax и сроком 8 часов.
Пароль — PBKDF2-HMAC-SHA256, 210000 итераций.
Фиксированная соль используется только для воспроизводимой демонстрационной учётной записи seed.

Каждый слот предназначен для одной услуги и бронируется целиком.
Длительность должна совпадать с длительностью услуги.
Интервалы полуоткрытые: соседние приёмы допустимы.
При бронировании выполняются SELECT FOR UPDATE выбранного слота и повторная проверка
действующих записей специалиста в одной транзакции. Отмена использует тот же слот как точку блокировки.

**Инвариант расписания:** слоты одного специалиста не пересекаются.
Генератор соблюдает его; операций ручного создания или изменения расписания нет.
Блокировка одного слота обеспечивает защиту повторного бронирования этого слота.
Проверка пересечений с уже существующими записями также выполняется.
Если в будущем появится запись произвольных пересекающихся слотов, одной блокировки выбранного слота
будет недостаточно для одновременного бронирования разных слотов: такую функцию здесь не реализуем.

Статусы: `booked` и `cancelled`. Отмена сохраняет историю и освобождает слот.
Повторная отмена не меняет первоначальное cancelled_at.
Время в БД хранится как timestamptz, в интерфейсе показывается по Москве.
Исторические слоты разрешено использовать: методичка не требует запрета бронирования прошедших дат.

Загрузка — занятые минуты / минуты расписания × 100.
При отсутствии расписания значение null, на странице «Нет расписания».
Доля отмен — отменённые / все записи, интервалы приёма которых пересекают выбранный период, × 100.
При отсутствии записей доля равна 0. Границы периода включают оба календарных дня в Москве.
Для сводки интервалы обрезаются границами периода; пересечения не учитываются дважды.
Список и поиск слотов фильтруются по дате начала приёма.

## Наполнение

`random.seed(42)`, фиксированные даты, идентификаторы и данные оператора.
Повторный запуск с одинаковыми параметрами окружения создаёт те же строки.
Вставки seed выполняются пакетами по 2000 строк; это только ускоряет подготовку стенда.

| Таблица | SMALL | WORKING |
|---|---:|---:|
| users | 1 | 1 |
| specialists | 10 | 200 |
| services | 10 | 30 |
| slots | 500 | 200000 |
| appointments | 300 | 100000 |

20% записей отменены. Длительности услуг — 30, 45 или 60 минут.
Слоты разных услуг одного специалиста располагаются на непересекающейся часовой сетке.
После вставок последовательности PK устанавливаются за последним seed-идентификатором.

## Тесты

```bash
docker compose run --rm app pytest -q
```

Используется реальный PostgreSQL и временная схема `sergey_rodionov_test_<случайный суффикс>`.
Она создаётся автоматически, наполняется перед каждым интеграционным тестом и удаляется после прогона.
Данные персональной рабочей схемы тесты не изменяют; SQLite не используется.

Проверяются правила интервалов и длительности, авторизация, cookie, отсутствие доступа,
справочники, свободные слоты, создание, занятый слот, пересечение с существующей записью,
отмена и повторное использование, фильтры, пагинация, карточка, сводка,
404/409/422, обязательные HTML-страницы и воспроизводимость seed по SHA256 всех строк.
Нет тестов параллельных гонок и отдельной системы CSRF-токенов.

## Контракт JSON API

Тело POST — JSON с Content-Type: application/json.
После входа клиент передаёт полученную cookie; браузер делает это автоматически.
Все операции, кроме входа, требуют авторизации.

| Метод и путь | Параметры / тело | Успешный ответ | Ошибки |
|---|---|---|---|
| POST /api/auth/login | login, password | 200: id, login, full_name; Set-Cookie | 401, 422 |
| POST /api/auth/logout | нет | 204 без тела; удаление cookie | 401 |
| GET /api/services | нет | 200: массив id, name, duration_minutes | 401 |
| GET /api/specialists | service_id > 0, необязательный | 200: массив id, full_name, specialization; услуга без специалистов даёт [] | 401, 422 |
| GET /api/slots | service_id, date_from, date_to; specialist_id; page=1, size=20 | 200: items свободных слотов, total, page, size | 401, 404, 422 |
| GET /api/appointments | page=1, size=20; status, specialist_id, service_id, date_from, date_to | 200: items записей, total, page, size | 401, 422 |
| GET /api/appointments/{id} | положительный id | 200: полная запись | 401, 404, 422 |
| POST /api/appointments | slot_id, client_name, client_contact | 201: полная созданная запись | 401, 404, 409, 422 |
| POST /api/appointments/{id}/cancel | положительный id | 200: полная отменённая запись; повторный вызов возвращает то же время отмены | 401, 404, 422 |
| GET /api/summary | date_from, date_to | 200: показатели сводки | 401, 422 |

Параметры дат — YYYY-MM-DD; date_to не раньше date_from.
Идентификаторы положительные, page ≥ 1, 1 ≤ size ≤ 100.
status — booked или cancelled. Длина ФИО и контакта 1–200 символов после удаления пробелов по краям.
Неизвестные поля POST отклоняются с 422.

Полная запись:
`id, status, client_name, client_contact, created_at, cancelled_at,`
`slot: {id, starts_at, ends_at}, specialist: {id, full_name, specialization},`
`service: {id, name, duration_minutes}, created_by: {id, full_name}`.
Список возвращает тот же формат каждой записи.

Свободный слот:
`id, starts_at, ends_at, specialist: {id, full_name}, service: {id, name, duration_minutes}`.

Сводка:
`date_from, date_to, total_appointments, cancelled_appointments, cancellation_percent,`
`specialists: [{specialist_id, full_name, scheduled_minutes, booked_minutes, load_percent}]`.

Даты и время JSON — ISO 8601 с часовым поясом; cancelled_at может быть null.
Список записей сортируется по starts_at DESC, id DESC;
свободные слоты — starts_at ASC, id ASC; справочники и специалисты сводки — id ASC.
total относится ко всему отфильтрованному набору; страница за его концом содержит пустой items.
Отсутствующие объекты при чтении карточки, бронировании и отмене дают 404.
Несуществующие идентификаторы в фильтрах списка дают пустой результат.
В поиске слотов отсутствующая услуга или специалист дают 404.
409 означает занятый слот, пересечение с записью или несоответствие длительности.

Ошибка предметной операции имеет вид `{"detail": "сообщение"}`.
Ошибка валидации FastAPI — `{"detail": [{loc, msg, type, ...}]}`.
При некорректных параметрах и отсутствии входа порядок проверки не считается гарантией:
корректный неавторизованный запрос получает 401, некорректный может получить 422.
Автоматическая схема: /openapi.json; интерактивная документация: /docs.

HTML-страницы — клиентский интерфейс, отдельный дублирующий контракт для них не ведётся.
Jinja2 вызывает общую бизнес-логику, минимальный JavaScript отправляет изменения в JSON API.

## Исходные измерения ДЗ1

Из корня проекта в WSL. Пересборка нужна после добавления инструмента:

```bash
docker compose build app
docker compose up -d app
docker compose run --rm app pytest -q

docker compose exec -T app python -m app.cli seed --size small
docker compose exec -T app python -m app.cli measure --size small --warmup 5 --repeats 30 --output measurements/small_baseline.json
docker compose exec -T app python -m app.cli seed --size working
docker compose exec -T app python -m app.cli measure --size working --warmup 5 --repeats 30 --output measurements/working_baseline.json
docker compose exec -T app python -m app.cli compare --small measurements/small_baseline.json --working measurements/working_baseline.json --output measurements/comparison.json
```

Не перезапускайте и не пересобирайте app между сравниваемыми сериями. Во время испытания
не запускайте другие запросы, тесты или seed: для подготовки изменений используется
та же БД. Это последовательное испытание одного клиента, а не нагрузочное тестирование.
Команда measure требует уже восстановленный seed соответствующего размера и проверяет
его количество строк. Seed внутри измеряемого интервала не выполняется.

Измеряются все 10 операций JSON API: вход, выход, услуги, специалисты, свободные слоты,
список записей, карточка, создание, отмена и сводка. Используется demo с id=1 на обоих
наборах. Фильтры слотов и сводки охватывают 2026 год; страница списка — 1, размер — 20.
Точные параметры каждого запроса сохраняются в JSON. HTML-рендеринг и работа браузера
в эти измерения не входят.

HTTPX из контейнера app обращается к работающему Uvicorn по HTTP/1.1,
http://127.0.0.1:8080; используется keep-alive, один последовательный клиент,
без перенаправлений и переменных proxy. Таймер perf_counter_ns охватывает отправку
HTTP-запроса и полное чтение ответа. На каждую операцию сначала выполняются 5
прогревочных запросов, затем 30 измеряемых. Прогрев обязателен, повторов минимум 20.
p50 и p95 вычисляются линейной интерполяцией позиции (n-1) × p в отсортированной
выборке; maximum — наибольшее измеренное время.

Перед отменой исходная активная запись восстанавливается. После создания удаляется
только запись с уникальным маркером данной серии и возвращается состояние её
последовательности PK. Перед выходом выполняется вход, перед входом очищаются cookie.
Вся подготовка и очистка находятся вне таймера; изменения не накапливаются.
Идентификаторы карточки, отменяемой записи и свободного слота выбираются до серии.
SHA256 всех строк и количество строк до/после должны совпасть; иначе результат
помечается failed и команда завершается ошибкой. Измерения требуют отдельного стенда
без других пользователей, поскольку восстановление последовательности безопасно
только при отсутствии параллельных записей.

В JSON сохраняются сырые повторы, агрегаты, условия (Python, библиотеки, PostgreSQL,
CPU, память, ограничения контейнера, параметры БД), версии исходников по SHA256,
учётная запись без пароля, число прогревов, период фильтрации и статус проверки данных.
Рядом создаются *_raw.csv и *_summary.csv. Каталог measurements смонтирован с хоста,
поэтому результаты сохраняются после пересоздания контейнера; в Docker image они не
копируются. Уже существующий путь --output перезаписывается — для новой серии задавайте
новое имя. Таблица агрегатов также выводится в терминал.

compare требует одинаковые условия, исходники, прогрев и число повторов. Кандидат
на дальнейшее исследование выбирается по заранее заданному правилу:
p50 WORKING / p50 SMALL ≥ 2 и абсолютный прирост p50 ≥ 5 мс. Это практическое правило
отбора, а не статистическая проверка значимости. Коэффициенты p50/p95 и разности
сохраняются для всех операций; объёмы таблиц растут неодинаково.

После сравнения для выбранных операций выполните отдельные диагностические серии.
В выполненном первичном сравнении выбраны free_slots, appointments_list, appointment_create, summary.
Для новых измерений замените список в --operations фактически выбранными именами из comparison.json:

```bash
docker compose exec -T app python -m app.cli seed --size small
docker compose exec -T app python -m app.cli measure --size small --warmup 5 --repeats 30 --diagnostic --operations free_slots,appointments_list,appointment_create,summary --output measurements/small_diagnostic.json
docker compose exec -T app python -m app.cli seed --size working
docker compose exec -T app python -m app.cli measure --size working --warmup 5 --repeats 30 --diagnostic --operations free_slots,appointments_list,appointment_create,summary --output measurements/working_diagnostic.json
```

--diagnostic включает наблюдение только для запросов с X-Measure-SQL: 1.
SQLAlchemy events before_cursor_execute, after_cursor_execute и handle_error
считают число выполнений SQL и суммарное время cursor.execute в контексте запроса.
SQL, параметры, ответы и бизнес-правила не меняются. X-Measurement-Id связывает
метрики с тем же запросом; заголовки отсутствуют в обычном режиме.
Документация событий: https://docs.sqlalchemy.org/en/20/core/events.html

Для каждого сырого повтора сохраняются http_total_ms, db_total_ms, db_query_count
и app_or_other_ms = http_total_ms - db_total_ms. В диагностической таблице агрегатов
эти четыре поля — средние арифметические одних и тех же 30 повторов;
p50/p95/max относятся к полному HTTP-времени. Число запросов также имеет min/max.
Не вычитайте SQL-среднее из HTTP-медианы.

SQL-время включает работу драйвера и обмен с PostgreSQL при выполнении запроса.
Оно не включает commit/rollback, отдельное извлечение результатов после execute,
ORM-обработку и подготовку соединения. Остаток включает эти действия, сериализацию,
HTTP-обмен и работу измерителя; это не чистое процессорное время Python.
Диагностический режим имеет собственные небольшие затраты наблюдения и сохраняется
отдельно от первичного сравнения. Индексы, кеширование и оптимизации не добавляются.

Тесты измерителя проверяют процентили, исключение прогрева/подготовки/очистки,
очистку при ошибке, сохранение данных и последовательности, подсчёт SQL включая
ошибки, отсутствие повторной установки обработчиков и утечки контекста,
неизменность SQL/ответа, связь заголовков с запросом, формат файлов и правило сравнения.

```bash
cd ~/oksp-coursework
python3 scripts/view_measurements.py --section small
python3 scripts/view_measurements.py --section working
python3 scripts/view_measurements.py --section comparison
python3 scripts/view_measurements.py --section diagnostic
python3 scripts/view_measurements.py --section inventory
```

Все таблицы: `python3 scripts/view_measurements.py`.
Другой каталог сохранённых файлов: `--directory /полный/путь/к/measurements`.

Вывод явно помечен как просмотр сохранённых результатов, содержит имя исходного
файла, дату серии в МСК/UTC, размер набора, прогрев и число измеряемых повторов.
Для comparison показаны даты обеих исходных серий: дата создания сравнения в
старом JSON не сохранялась. Диагностические HTTP/SQL/остаток — согласованные
средние одних и тех же повторов, а не медиана минус среднее.

просмотра существующих JSON переключение наполнения не требуется.
